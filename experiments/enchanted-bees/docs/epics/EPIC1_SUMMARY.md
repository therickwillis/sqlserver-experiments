## Overview

Built a complete database migration generation system that automatically creates timestamped migration scripts from SQL Server Database Project (SSDT) schema changes using DACPAC comparison.

## What We Built

### Core Features

1. **DACPAC-Based Schema Comparison**
   - Compares current SQL project against baseline DACPAC
   - Uses `sqlpackage` DeployReport and Script actions
   - Detects all schema changes (CREATE, ALTER, DROP)

2. **Baseline Management**
   - Stores baseline DACPACs in `.dbctl/baselines/`
   - Filename format: `EnchantedBeesDB_{hash}.dacpac`
   - Updates baseline after successful migration generation

3. **Migration File Generation**
   - Timestamp-based naming: `YYYYMMDDHHMMSS_description.sql`
   - Auto-generates description from schema changes
   - Supports custom descriptions via `-m` flag
   - Includes metadata header with checksum

4. **Rollback (DOWN) Migrations**
   - Auto-generates `.down.sql` files
   - Template for manual rollback implementation
   - Documents non-reversible changes

5. **CLI Integration**
   - `dbctl generate` - Generate migration from changes
   - `dbctl generate --init` - Initialize baseline
   - `dbctl generate -m "description"` - Custom description

## Technical Implementation

### DACPAC Comparison
```bash
sqlpackage /Action:DeployReport \
  /SourceFile:current.dacpac \
  /TargetFile:baseline.dacpac \
  /TargetDatabaseName:TempDB \
  /OutputPath:report.xml
```

### Migration File Format
```sql
-- =============================================
-- Migration: 20260127135153_add_api_key_table
-- Generated: 2026-01-27T13:51:53.279127
-- Baseline DACPAC: c1b108e3488c
-- Checksum: 5888c498846d6817013dd98843f0b2f6393af5ef4352ddd577363c2274387cbf
-- =============================================

[SQL generated by sqlpackage]
```

## Challenges Overcome

1. **DACPAC Comparison Parameters**
   - Issue: DeployReport failed without `/TargetDatabaseName`
   - Solution: Added `/TargetDatabaseName:TempDB` to both DeployReport and Script actions

2. **SQL Server Version Compatibility**
   - Issue: SQL project targeted SQL 2022, but Azure SQL Edge is SQL 2019
   - Solution: Changed DSP from `Sql160DatabaseSchemaProvider` to `Sql150DatabaseSchemaProvider`

3. **Checksum Calculation**
   - Issue: Needed stable checksums for migration integrity validation
   - Solution: SHA256 hash of migration file content

4. **Auto-Description Generation**
   - Issue: Generating meaningful descriptions from schema changes
   - Solution: Parse DeployReport XML, extract change types and object names

## Architecture Decisions

### Why DACPAC Comparison?
- **Declarative schema**: SQL project defines desired state
- **Automatic change detection**: sqlpackage handles complex schema diffs
- **Production-grade**: Same tool used by SSDT and Azure DevOps
- **Cross-platform**: Works on Mac (ARM64) and Windows

### Why Baseline Tracking?
- **Incremental changes**: Only generate migrations for new changes
- **Git-friendly**: Baseline hash in filename ensures uniqueness
- **Rollback support**: Can regenerate from any baseline

### Why Timestamp-Based Naming?
- **Chronological ordering**: Natural sort order
- **Merge conflict avoidance**: Different devs get different timestamps
- **UTC timestamps**: Consistent across timezones
